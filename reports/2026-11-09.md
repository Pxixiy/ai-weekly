## 本周研判

### 01 · 智能体治理

**智能体治理从“倡议”进入“准入”：身份、OTA 与成熟度评估同时收紧**

同一周内，自律公约（11/04）、工信部 42 号文（11/06）、工业智能体成熟度国标公示（11/11）与杭州 AI 产业条例草案（11/11）接连落地。治理工具从原则倡议转向可检查的准入项：终端智能体要有唯一身份码、OTA 变更须专家评估、成熟度模型给出评估流程。对做 agent 平台与终端的团队，合规清单正从表态变成检测项，身份与版本管理需要前置到研发流程。

依据：[42 号文](http://rss.jingjiribao.cn/static/detail.jsp?id=695708) · [自律公约](https://finance.sina.com.cn/wm/2026-11-04/doc-inixqnsy6774673.shtml) · [国标公示](https://std.samr.gov.cn/gb/search/gbDetailed?id=511E143A4E4160FEE06397BE0A0A2642) · [杭州条例](https://hzdaily.hangzhou.com.cn/mrsb/2026/11/11/article_detail_3_20261111A041.html)

### 02 · 身份与发现

**智能体的“身份”与“授权”开始分层：DNS 命名之外，还需要权限衰减**

Linux 基金会 ANS（11/10）用 DNS 与网站证书体系解决智能体的命名、注册、发现与互认；NIST 十原则（10/27）与 CSA 解读（11/09）则把重点放在“能干什么”：按任务衰减权限、策略决策点放在模型之外、确定性规则判定。两层标准正在分离——命名/发现层趋向互联网基础设施，授权层仍是企业自建。做 agent registry/discovery 的产品，需要同时对接可验证身份与可审计授权，而不是只做目录。

依据：[ANS](https://www.linuxfoundation.org/press/linux-foundation-welcomes-agent-name-service-to-bring-verifiable-identity-and-discovery-to-ai-agents) · [NIST 十原则](https://labs.cloudsecurityalliance.org/research/csa-research-note-nist-agent-identity-design-tenets-20261109/)

### 03 · 运行时安全

**智能体安全从“事后披露”转向“运行时管控”**

OpenAI 的 Control Room（11/09）给每个任务发唯一 ID、关联安全论证，异常时 35 秒内叫停；WorkOS 事件（11/11）说明测试环境隔离与网络出口仍是薄弱点；Cequence 报告（11/11）给出量化：25 万次智能体访问中约 1/7 完成登录、下单或购买，启用护栏后越权动作从 44% 降至 1%。三件事指向同一结论：任务级身份、可终止性与运行时护栏，正在从“最佳实践”变成平台标配。

依据：[Control Room](https://m.sohu.com/coo/zmtq/1100292086_161795) · [WorkOS 事件](https://www.cnetsec.com/article/44077.html) · [Cequence 报告](https://www.sourcesecurity.com/tags/video-analytics/news/cequence-agentic-ai-runtime-security-report-co-1654677090-ga.1794466782.html)

### 04 · 前沿模型

**前沿模型竞争转向“便宜 + 可编排”**

Gemini 4 Hydrogen（11/12）把四档推理强度、长上下文与低价组合在一起，Antigravity Orchestrator 可在同一任务中切换 Carbon/Hydrogen；百度文心 5.5 Flash（11/12）以 2800 亿总参、140 亿激活、100 万上下文对标，并上线“词元所”交易平台。竞争焦点从单模型分数转向单位 token 成本与多模型调度。对 agent 平台，模型路由、成本核算与失败回退将比“选一个最强模型”更重要。

依据：[Gemini 4 Hydrogen](https://www.eet-china.com/mp/a539086.html) · [文心 5.5 Flash](https://www.cnr.cn/bj/sijh/20261112/t20261112_527870324.shtml)

### 05 · 国际治理

**自愿联盟与司法挑战并行，前沿模型治理进入“多轨”**

马克龙召集的“人工智能安全巴黎倡议”（11/09）由八国签署，承诺加强前沿模型风险的独立与公共评估、严重事件预警共享、开发者责任；三天后，美国四家非营利组织起诉 Anthropic、谷歌、Meta、OpenAI 及 SpaceX 旗下 AI 企业，要求法院阻止继续研发。一边是自愿联盟，一边是司法强制，治理从政策场扩展到诉讼场；企业的发布节奏、披露口径与安全论证留痕，将同时受两套机制约束。

依据：[巴黎倡议](https://www.sohu.com/a/1100668847_114911) · [五巨头诉讼](http://biznews.sohu.com/a/1101095940_115479)

## 智能体互联与发现

### Linux 基金会启动 Agent Name Service：用 DNS 为智能体提供可验证身份与发现入口

- 日期：2026-11-10
- 来源：Linux Foundation
- 发布：Linux Foundation
- 状态：项目启动

ANS 成为 Linux 基金会新项目，基于 DNS 与网站证书体系定义智能体命名与注册、身份发布与校验、公共日志审计、完整性监控与智能体互认；规范由 7 份文档组成，11 家机构支持，AGNTCY 已接入，GoDaddy、Cloudflare、Salesforce、DigiCert 等参与。

**智能总结**：智能体发现从私有注册表走向互联网级基础设施；DNS 锚定命名 + 身份校验若被采纳，可能成为跨平台互操作的事实标准，直接影响 agent registry/discovery 的产品路线与技术选型。

[原文](https://www.linuxfoundation.org/press/linux-foundation-welcomes-agent-name-service-to-bring-verifiable-identity-and-discovery-to-ai-agents)

### CSA 解读 NIST 智能体身份十原则：防提示注入要靠“权限衰减 + 外部策略点”组合

- 日期：2026-11-09
- 来源：云安全联盟 CSA
- 发布：NIST / 云安全联盟 CSA
- 状态：框架解读

NIST 10 月 27 日提出智能体身份十项设计原则；CSA 11 月 9 日分析指出，应按任务衰减权限、把策略决策点放在模型之外、用确定性规则判定，并配合持续监控与高风险人工升级；单点控制不足以抵御提示注入。

**智能总结**：为“智能体身份/授权”给出可落地的控制组合，与 ANS 的命名认证互补：一个解决“你是谁”，一个解决“你能干什么”。对做 agent 安全网关、权限中台的团队，这是可以直接映射到产品架构的检查表。

[原文](https://labs.cloudsecurityalliance.org/research/csa-research-note-nist-agent-identity-design-tenets-20261109/)

### OpenAI 部署“Control Room”：35 秒内叫停失控智能体

- 日期：2026-11-09
- 来源：南方都市报
- 发布：OpenAI
- 状态：已部署

11 月 9 日公告：系统统一追踪强化学习实验、模型评估、大规模采样与数据处理作业，每个任务须申请唯一 ID 并关联获批的安全论证；异常时标记停止，最长 35 秒生效，延迟来自推理授权缓存层，目标降至 0。

**智能总结**：把智能体安全落到运行时：任务级授权 + 可终止性。对 agent 平台是“kill switch + 任务身份”的参考架构；35 秒的延迟也说明，终止能力受制于缓存与调度层，需要从架构上预留快速熔断通道。
